# Movie Review Library and Unified Search Design

## Goal

Add a private movie-review corpus sourced from the official TMDB API and make
it searchable alongside the existing timestamped subtitle corpus. Review data
remains structurally and operationally separate from subtitle dialogue, while
the workbench presents one search entry point with `All`, `Dialogue`, and
`Reviews` scopes. A review result can seed video creation as a theme, but review
prose is never represented as movie dialogue.

## Decisions

- Use TMDB's official API instead of scraping review websites.
- Store reviews and review chunks in dedicated tables.
- Keep the existing subtitle search contract available for compatibility.
- Add a unified library-search contract that returns typed dialogue and review
  results.
- Generate review and query embeddings with Supabase Edge Runtime's built-in
  `gte-small` model. No external embedding API is required.
- Fetch English reviews in the first version because `gte-small` is an English
  embedding model. Chinese user queries continue through the existing Ollama
  normalization path before search.
- Let a review result create a video only by deriving a theme and finding real,
  timestamped dialogue. The output manifest records both review inspiration and
  subtitle provenance.
- Keep the feature inside the existing loopback-only personal research
  workbench and preserve the current custom personal-token boundary.

## Alternatives Considered

### Separate corpora with unified retrieval (selected)

Reviews and subtitles have independent schemas, ingestion paths, full-text
indexes, vector indexes, and provenance. A unified Edge Function retrieves from
one or both corpora and merges ranked results. This adds a small amount of
aggregation logic but keeps ownership and rights boundaries explicit.

### Generalized content index

A new polymorphic document and chunk model could represent subtitles, reviews,
and future sources. This is attractive long term, but it would require a risky
rewrite of stable subtitle ingestion, timestamp anchoring, and video provenance.

### Reviews in `subtitle_chunks`

This would reuse the current search function with minimal code, but review
authors, ratings, URLs, and publication timestamps do not fit subtitle
semantics. It would also allow review prose to be mistaken for timed dialogue.
This option is rejected.

## External Research

- TMDB's `GET /find/{external_id}` endpoint supports IMDb IDs, so the existing
  `movies.imdb_id` value is the authoritative mapping input:
  <https://developer.themoviedb.org/reference/find-by-id>
- TMDB exposes paginated movie user reviews through
  `GET /movie/{movie_id}/reviews`, with `language` and `page` parameters:
  <https://developer.themoviedb.org/reference/movie-reviews>
- TMDB permits non-commercial API use with required attribution. The workbench
  must include the required TMDB notice and link in its credits/about surface:
  <https://developer.themoviedb.org/docs/faq>
- Supabase Edge Functions can run the built-in `gte-small` embedding model
  without an external model API. The model is English-only and truncates long
  inputs, so review text must be chunked before inference:
  <https://supabase.com/docs/guides/functions/ai-models>
- Supabase recommends short-lived, idempotent Edge Functions; heavy or
  long-running work should be split into resumable operations:
  <https://supabase.com/docs/guides/functions>

## Data Model

### `public.movies`

Add nullable `tmdb_id bigint` with a partial unique index. It is resolved from
the movie's IMDb ID and cached after the first successful TMDB lookup. The IMDb
ID remains the source identity; title search is not used as an automatic
fallback because it can silently associate the wrong film.

### `public.movie_reviews`

- `id bigint generated by default as identity primary key`
- `movie_id bigint not null references public.movies(id) on delete cascade`
- `source text not null default 'tmdb'`
- `source_review_id text not null`
- `author text not null`
- `author_username text`
- `rating numeric(3,1)` constrained to TMDB's accepted range when present
- `language_code text not null default 'en'`
- `content text not null`
- `source_url text not null`
- `published_at timestamptz`
- `source_updated_at timestamptz`
- `fetched_at timestamptz not null default now()`
- `content_sha256 text not null`
- `rights_status text not null default 'personal_research'`
- unique key `(source, source_review_id)`

Provider URLs are validated against the HTTPS `www.themoviedb.org` origin
before storage. Content is bounded and normalized without rewriting the review.
The content hash makes unchanged reviews cheap to skip.

### `public.movie_review_chunks`

- `id bigint generated by default as identity primary key`
- `review_id bigint not null references public.movie_reviews(id) on delete cascade`
- `chunk_index integer not null`
- `content text not null`
- generated English `tsvector` column for full-text retrieval
- `embedding extensions.vector(384) not null`
- unique key `(review_id, chunk_index)`

Chunks are split on paragraph and sentence boundaries and then bounded below
the `gte-small` truncation limit. The table receives a GIN index for full-text
search and an HNSW cosine index for vector search.

### `public.movie_review_sync_state`

One private row per movie records the cached TMDB ID, status, next page,
reported total pages, fetched review count, last error code, timestamps, and a
run identifier. This state supports refresh recovery and page-by-page retries.
It stores no access token or raw upstream error body.

All three review surfaces are private. RLS is enabled without browser-facing
policies, Data API grants are revoked, and only service-role Edge Functions or
explicit private RPCs can read or mutate them.

## Database Contracts

### Atomic review-page ingestion

`private.ingest_movie_review_page(...)` accepts one validated TMDB page plus
its precomputed chunk embeddings. In one transaction it:

1. locks the movie's sync-state row;
2. upserts reviews by provider identity;
3. replaces chunks only when the content hash changed;
4. advances the page cursor and counters;
5. marks the movie complete when no next page remains.

A request digest makes retries idempotent. A failed transaction does not leave
a review without its expected chunks.

### Review hybrid search

`private.hybrid_movie_review_search(...)` performs semantic and English
full-text retrieval and combines both lists with weighted reciprocal rank
fusion. It returns review metadata and chunk excerpts but never returns an
embedding. Results are deduplicated by review so one long review does not fill
the result set with adjacent chunks.

### Unified ranking

The Edge Function asks each selected corpus for more candidates than the final
limit. Each corpus preserves its internal hybrid rank. For `All`, a second
reciprocal-rank merge combines corpus ranks with equal type weight and a stable
tie break. Raw cosine distances from different corpora are not presented as a
shared percentage. Dialogue-only and review-only searches retain their native
ordering.

## Edge Functions

### `movie-review-sync`

The function uses the existing constant-time `x-subtitle-token` authentication
and reads `TMDB_ACCESS_TOKEN` only from Supabase project secrets. Supported
operations are:

- resolve and cache a TMDB movie ID from a validated IMDb ID;
- fetch and ingest one review page;
- return a sanitized per-movie sync status;
- return bounded aggregate review-library counts.

One invocation processes at most one provider page. The local workbench
controller advances through pages and movies, persists a sanitized snapshot,
and exposes cooperative stop behavior just like subtitle synchronization. TMDB
429 and transient 5xx responses use bounded retry/backoff information; auth,
mapping, quota, and malformed-provider failures receive stable internal error
codes.

### `hybrid-library-search`

Input:

```json
{
  "query": "hope after a long period of confinement",
  "scope": "all",
  "limit": 20,
  "movieId": 1
}
```

`scope` is one of `all`, `dialogue`, or `reviews`. `movieId` is optional. The
function generates one normalized query embedding, calls the selected private
RPCs, loads subtitle cues for dialogue results, merges ranks, and returns a
discriminated result union. Query and limit bounds match the current subtitle
search boundary. The existing `hybrid-subtitle-search` function remains
unchanged for existing clients.

## Workbench API and UI

The loopback service adds:

- `POST /api/library/search`
- `GET /api/reviews/library`
- `GET /api/reviews/sync`
- `POST /api/reviews/sync`
- `POST /api/reviews/sync/stop`
- `GET /api/reviews/sync/events`

Mutation routes retain the boot token and same-origin validation. Secrets,
provider request URLs, local paths, and raw provider errors never enter browser
JSON.

The current library view becomes a unified content search surface:

- a segmented `All / Dialogue / Reviews` scope control defaults to `All`;
- dialogue rows preserve movie, year, timestamp, text, rank labels, and the
  exact-quote creation action;
- review rows show movie, author, optional rating, publication date, a bounded
  excerpt, rank labels, a TMDB source link, and `Create from this viewpoint`;
- subtitle and review synchronization are distinct commands and progress
  panels because their providers, quotas, and terminal states differ;
- search query, selected scope, result count, results, warnings, and scroll
  position remain mounted across navigation so switching views does not erase
  completed retrieval work;
- the credits/about surface includes TMDB's required attribution notice.

## Review-Driven Video Creation

Selecting `Create from this viewpoint` records the source review ID and sends a
bounded review excerpt to the existing Ollama-backed normalization service. It
produces a concise English theme, not replacement dialogue.

The pipeline then:

1. searches timestamped subtitle chunks from the reviewed movie with the
   derived theme;
2. anchors the highest-ranked valid match and asks the existing passage service
   for the requested 5-10 consecutive scenes;
3. falls back to an all-movie subtitle search only when the reviewed movie has
   too few valid timed cues, and reports that fallback in the task;
4. uses the selected dialogue and derived visual concepts for the existing
   three-route Vecteezy candidate search;
5. continues through the existing review, selection, download, FFmpeg render,
   and Supabase metadata-writeback flow.

Scene duration always comes from selected subtitle timestamps. The review text
is neither rendered as a quotation nor placed in the bilingual subtitle track.
The v2 manifest adds review source identity, source URL, derived theme, and
whether subtitle selection stayed within the reviewed movie.

## Error Handling

- Missing local configuration disables review sync with a controlled message.
- Missing remote `TMDB_ACCESS_TOKEN` returns `configuration_error` without
  revealing environment details.
- A movie without an IMDb ID is skipped with `missing_imdb_id`.
- No `/find` match produces `tmdb_movie_not_found`; automatic title fallback is
  not attempted.
- Ambiguous or malformed TMDB payloads produce `provider_contract_error`.
- Rate limiting produces a resumable `rate_limited` state and preserves the
  current page.
- A page with one malformed review rejects that review but can ingest other
  valid entries while recording a bounded warning count.
- Embedding or database failure leaves the page cursor unchanged, so retrying
  cannot silently omit content.
- Review-theme generation failure keeps the review result usable for reading
  but blocks its video action with a controlled retry state.
- No relevant timed dialogue returns a clear empty state and does not start a
  Vecteezy or render job.

## Security, Privacy, and Rights

- Store the TMDB token only in `.env` for local orchestration and in Supabase
  project secrets for deployed Edge Functions. Never commit or return it.
- Permit provider requests only to fixed HTTPS TMDB API origins. Do not accept
  arbitrary fetch URLs from callers.
- Treat author names, review prose, and provider fields as untrusted data.
- Keep review tables private and use bounded inputs, outputs, page counts,
  content length, timeouts, and embedding concurrency.
- Preserve source links and `personal_research` rights metadata.
- Show excerpts in the workbench and do not add bulk review export or public
  corpus endpoints.
- Display TMDB's required attribution and do not imply TMDB endorsement.

## Verification

- Database tests cover private access, RLS and grants, uniqueness, cascade
  behavior, URL constraints, atomic page retry, review deduplication, FTS,
  vector search, and reciprocal-rank ordering.
- Shared contract tests cover TMDB mapping, pagination, malformed records,
  hashes, chunk bounds, provider URL validation, and stable error codes.
- Edge Function tests cover authentication, one-page limits, idempotent retry,
  rate limiting, missing IMDb/TMDB mappings, result redaction, all three search
  scopes, and deterministic cross-corpus ranking.
- Workbench service tests cover Chinese normalization fallback, sync snapshot
  recovery, cooperative stop, mutation authorization, SSE, and response
  redaction.
- React tests cover scope persistence, typed result rendering, source links,
  independent sync controls, navigation persistence, and both creation actions.
- Playwright covers unified search, switching away and back without losing
  results, a review result creating a real subtitle-anchored task, and review
  synchronization with fixtures.
- Before deployment, run Vitest, typecheck, production build, Playwright, pgTAP,
  Supabase security/performance advisors, and a live read-only search smoke.
- After deployment, run one bounded remote TMDB sync probe. Local DNS currently
  resolves the TMDB API incorrectly, so provider connectivity must be verified
  from the deployed Edge Function rather than inferred from the local machine.

## Rollout

1. Apply the private review schema and RPCs without changing existing search.
2. Deploy review sync and verify one movie through the remote Edge runtime.
3. Backfill reviews for existing movies through the resumable workbench loop.
4. Deploy unified search while retaining the old subtitle endpoint.
5. Enable the unified UI and review-driven video action.
6. Review advisors, logs, attribution, and stored provenance before broader use.

## Non-Goals

- Scraping IMDb, Douban, Rotten Tomatoes, or arbitrary review websites.
- Translating and storing review bodies in the first version.
- Presenting review prose as a film quotation or using it as subtitle timing.
- Training a model with subtitle, review, or Vecteezy content.
- Publishing a public review archive or bulk-download API.
- Replacing the existing subtitle ingestion or video production pipeline.
